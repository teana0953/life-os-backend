# Tasks

**後端 only。** 前端(設定頁的金鑰、助手畫面、確認卡)是分開的 change。

## 0. 契約

- [ ] 0.1 `POST /api/assistant`,body 帶對話(角色 + 內容),回一段文字 + 零或多張提議卡。
- [ ] 0.2 金鑰走 `X-Gemini-Api-Key` **header**。**不是** query。
- [ ] 0.3 對 Gemini 也用 `x-goog-api-key` header,**不是** `?key=`。官方範例是後者。

## 1. 金鑰

- [ ] 1.1 解析集中在**一個**函式:拿到一把 key,或一個明確的錯誤。
- [ ] 1.2 **突變:把那把 key 放進回應的任何欄位**,一條「任何回應都不含金鑰」的測試必須紅 —— 而且要涵蓋**每一條錯誤路徑**,不是只有成功那條。
- [ ] 1.3 **突變:改成從 query 讀**,必須紅。
- [ ] 1.4 沒有金鑰 → 400 + 指名是哪個設定,不是 500。

## 2. 工具

- [ ] 2.1 工具定義中立(名字 / 描述 / JSON schema / 處理函式),adapter 翻成 Gemini 的 `functionDeclarations`。
- [ ] 2.2 每個工具呼叫既有的 use case,帶**呼叫者的** `userId`。**不新增任何 repository 方法**,也不寫 SQL。
- [ ] 2.3 **突變:讓某個工具吃 body 傳來的 userId**,一條「問不到別人的資料」的測試必須紅。
- [ ] 2.4 讀的工具:記帳月摘要、分類清單、交易清單、預算進度、分帳餘額。
- [ ] 2.5 寫的工具**只有**「新增一筆交易」,而且**只回提議**。
  **突變:讓它真的寫**,一條「呼叫後資料庫沒有新列」的測試必須紅。
- [ ] 2.6 **沒有任何寫分帳的工具。** 突變:加一個,一條「工具清單」的測試必須紅 —— 這條要斷言**整份清單**,不是「不包含某個名字」。

## 3. 迴圈

- [ ] 3.1 模型要工具 → 執行 → 回結果 → 再問。**上限要有**,而且超過上限要**說出來**,不是安靜截斷。
- [ ] 3.2 模型要一個不存在的工具 → 回錯誤給模型,不是 500。
- [ ] 3.3 工具參數不符 schema → 同上。

## 4. 錯誤

- [ ] 4.1 金鑰無效 / 額度用盡 / 模型無權限 —— **三種分開**。
- [ ] 4.2 **突變:三種收斂成一種**,必須紅。需要三個 fixture 各自落在一種上(**兩個一樣的 fixture 證明不了分得開**)。

## 5. 範圍

- [ ] 5.1 沒有任何工具碰健康 / 飲食 / 照護 / 提醒。斷言**整份清單**。
- [ ] 5.2 送給模型的是彙總,不是交易列。**突變:把整批交易塞進上下文**,一條測試必須紅。

## 6. 驗證

- [ ] 6.1 `npm test`、`npm run typecheck` 全綠。
- [ ] 6.2 Gemini 的 HTTP 呼叫用 fake fetch,不打真的網路。
