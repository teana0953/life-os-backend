## Why

issue #129:記帳時多一個分期的選項,自動在往後每個月產生明細。

**這是一張「固定期數的真實扣款時程表」**,不只是信用卡分期。同一個機制吃下三種:

| 情境 | 走哪條 |
|---|---|
| 信用卡分期 12 期 | **總額 ÷ 期數** |
| 綁約 N 個月的訂閱 | **每期金額 × 期數** |
| 房貸 / 車貸 | 同上 |

**年繳訂閱不走這裡。** 付一次、用 12 個月 —— 那是攤提,跟分期的現金流方向相反(分期是買一次付 N 次)。決定是**帳本對得上銀行**:年繳就是繳費當月的一筆普通交易,後面 11 個月沒有列。把它攤成 12 筆會讓一月的帳本說 1,000 而對帳單說 12,000,而預算警示與分帳鏡像都是對真實現金響的,混進攤提出來的虛擬金額之後,預算就不再是在量現金。

**跟人分帳的年繳要每月顯示**是另一件事:一筆分帳現在只產生一筆鏡像交易,要做到雙方都看到每月 500,得讓分帳本身帶時程表 —— 那是 split context 的改動,不在這裡。

## 範圍界線:這是一張金額時程表,不是財務模型

**不存利率、不算攤還、不推算任何金額。** 房貸的月付金牽涉利率、寬限期、指數型調息、提前還款違約金 —— **app 算出 32,145 而銀行實際扣 32,148,帳本就是錯的**,而使用者會因此不再信任它。銀行才是權威,數字從銀行抄過來。

| | 總額模式(信用卡) | 每期金額模式(訂閱/貸款) |
|---|---|---|
| 建立 | **總額** + 期數 → 系統平均分配 | **每期金額** + 期數 → 直接照抄,**不做除法** |
| 清償 | 系統算剩餘期數之和 | **金額由使用者從銀行抄**(見下) |
| 利率 | 不存 | **不存** |

**清償金額對貸款必須是使用者輸入的。** 第一版讓系統一律用「尚未發生的期數之和」—— 但對貸款而言**那個和裡面含著未來的利息**,真正的清償金額是剩餘本金加違約金。那會是整個 change 裡唯一一處系統自己推算金額的地方,直接違反上面那條界線。

**部分提前還款不是一個功能**,是「記一筆 + 改整組」的組合。照銀行規則,信用卡分期本來就不提供部分提前(只有照月繳或一次清償)。

## What Changes

- 新增 `finance_installment_plan`,交易上加可空的 `plan_id` 與 `installment_no`。
- 建立時**就把 N 筆真實交易寫進去**,每月一筆,日期從起始日錨定推算。
- 整組可改(金額/期數),**只重寫尚未發生的期數**,而「尚未發生」以**使用者的今天**為準。
- **一次清償**:刪掉尚未發生的期數,在今天插一筆(信用卡=系統算的和;貸款=使用者輸入)。

### Modified Capabilities

- `finance-ledger`:新增分期。

## Impact

- **真正 `SUM(finance_transaction.amount)` 的只有兩處**:預算的 `spentSum` 與 `getMonthlySummaryRaw`。**淨值與趨勢不讀這張表**(讀 `finance_networth_snapshot`,是手動的月快照)。所以分期寫成普通交易列之後那兩處不用改 —— 但也代表**360 期的房貸永遠不會動到淨值**,貸款餘額停在使用者上次輸入的快照。刻意如此,但要讓使用者知道。
- **預算警示會被未來的月份燒掉。** `createTransaction` **與 `updateTransaction`** 都會呼叫 `checkBudgetAlerts`,它用交易自己的月份當 key,而 `finance_budget_alert` 對 (budget, month, threshold) 唯一。**只要某個月的累計跨過門檻**(房貸月付很容易),那個月的警示列現在就被寫掉,**真的到那個月時永遠不會響**。規則定為**只對「月份 ≤ 使用者的今天」觸發** —— 不是「分期一律不觸發」,後者會壓掉清償那一筆的當月警示,而它是這個功能能產生的最大一筆支出。
- **期數上限:房貸是 360 期**,而 neon-http `db.batch` 的語句數上限**查不到**(drizzle → 一個 HTTP POST,driver 與 Neon 文件都沒說)。所以**不要用「一期一句」的寫法** —— 用**單一 multi-row INSERT** 建立、**單一 `DELETE WHERE user_id AND plan_id AND day > ?`** 清除,語句數與期數無關。
- **月份推進要從起始日錨定**(`+ interval 'N month'`),不是逐次遞增 —— 後者從 1/31 開始會漂移成 2/28 → 3/28 且再也回不去。
- **後端沒有小數位的概念**(`amount` 只是 `integer`,`SUPPORTED_CURRENCIES` 沒有 metadata),所以除不盡的差額永遠是 1、與幣別無關。
- **預算的 `spentSum` 寫死 `currency = 'TWD'`**,所以非 TWD 的分期不會出現在預算進度裡。
- **「今天」要用使用者的時區**,而財務 context 從來沒讀過 `users.timezone` —— 分期是第一個。
- 只做後端;前端是下一個 change。
