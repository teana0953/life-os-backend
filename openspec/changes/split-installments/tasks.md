# Tasks

**餘額語意不變是這個 change 的地基**(見 proposal 的裁定)。任何讓餘額按到期日分段的實作都是錯的 —— 那會讓債在還沒到期時消失。

## 0. 盤點

- [ ] 0.1 **`finance_transaction_user_split_expense_idx` 是 `(user_id, split_expense_id)` 的唯一索引** —— 一人一筆分帳只能有一筆鏡像。一人 N 筆要改它,而**改法決定了鏡像的身分鍵**:`(user_id, split_expense_id, installment_no)`。
- [ ] 0.2 餘額查詢(`drizzle-balance-repository.ts`)有 `HAVING SUM(...) != 0` —— **零餘額整列不見**。這是「不按到期日分段」的決定性理由,寫進註解。
- [ ] 0.3 確認 `SharesMirror.plan` 現在的形狀(`MirrorPlanInput` → `ShareMirrorRow[]`,一人一筆)。

## 1. 時程表

- [ ] 1.1 分帳支出可帶還款時程表(期數 + 每期金額 / 總額平均分)。
- [ ] 1.2 **月份從起始日錨定**,不是逐次遞增 —— 從 1/31 開始逐次遞增會漂成 2/28 → 3/28 且回不去(#82 踩過)。**fixture 必須從 1/31 開始,而且斷言第三期** —— 兩種寫法對第二期都同意。
- [ ] 1.3 除不盡的差額固定是 1(`amount` 是 integer,沒有小數位概念)。fixture 用**除不盡**的總額。

## 2. 鏡像:條件反轉,不是相加

- [ ] 2.1 有時程表 → **每期一筆鏡像,不記那筆總額的分攤**;沒有 → 照舊一筆。
- [ ] 2.2 **突變:兩者都記**(總額 + 期數),一條「該分攤者這筆支出的鏡像總和等於分攤額」的測試必須紅。6,000 + 12×500 = 18,000 是這條要擋的。
- [ ] 2.3 **突變:有時程表時仍只記一筆總額**,一條「帳本裡是 12 筆 500」的測試必須紅。
- [ ] 2.4 **突變:沒有時程表的分攤也被拆開**,一條「無時程表 → 一筆」的測試必須紅。**這條不能少** —— 少了它,「一律拆開」會活下來。

## 3. 餘額不動

- [ ] 3.1 餘額仍是 `SUM(shares) − SUM(settlements)`,**與時程表無關**。
- [ ] 3.2 **突變:讓餘額只算已到期的期數**,一條「剛建好、一期都還沒到期 → 餘額仍是全額,而且那一列存在」的測試必須紅。**「那一列存在」是重點** —— `HAVING != 0` 會讓它整個消失,只斷言金額的話看不出差別(找不到列 vs 金額為零)。
- [ ] 3.3 **排定要還 ≠ 已經還了。** 突變:讓期數日期一到就自動減少餘額,一條「兩期日期已過但沒有記錄還款 → 餘額不變」的測試必須紅。
- [ ] 3.4 **不自動產生 `split_settlement`。** 實際還款仍由使用者記錄。

## 4. 進度隨餘額一起回

- [ ] 4.1 `GET /api/split/balances` 每一列多帶:下一期是第幾期、共幾期、那一期的金額。
- [ ] 4.2 沒有時程表的那些列**不帶進度欄位**(不是帶零)—— 前端才分得出「沒有時程表」與「時程表跑完了」。
- [ ] 4.3 **突變:所有列都帶進度**(沒時程表的填零),4.2 必須紅。

## 5. 身分鍵與寫入

- [ ] 5.1 唯一索引改成 `(user_id, split_expense_id, installment_no)`。
- [ ] 5.2 **語句數與期數無關**:建立單一 multi-row INSERT、清除單一 DELETE(#82 的做法)。`neon-http` 的 `db.batch` 語句數上限查不到。
- [x] 5.3 編輯分帳時,鏡像的更新仍在**同一個 `db.batch`**(既有的原子性要求)。**這條原本被跳過,而跳過的後果是可觸及的 500**:`schedule` 已經接上 `PATCH /api/split/expenses/:id`,所以使用者建得出帶時程表的分帳、也編輯得到,而編輯**必定**在唯一索引上炸掉 —— 每一筆這種分帳只能建立一次、之後任何修正都是 500。
- [x] 5.3a `ON CONFLICT` 一次只能指定一個目標,而鏡像有兩個部分索引(整筆 / 期數),所以要**兩個 upsert**。把期數送去整筆那個目標不只是「沒對到」—— 期數索引接著會丟未處理的唯一違規,整筆編輯失敗。
- [x] 5.3b **縮短期數要另外刪**:被砍掉的期數沒有東西可以衝突,upsert 碰不到它們,會變成孤兒繼續向分攤者收那些已經不存在的期數。集合式的(只需要最大期數),不需要知道編輯前的形狀。
- [ ] 5.4 **突變:改成一期一句**,一條 360 期的 PGlite 測試必須紅。
